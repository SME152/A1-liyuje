========================================================================
 PROG2004 Object Oriented Programming - Assessment 1
 Appointment system for a health service
 Li Yuje
========================================================================

 This program builds the object model for an appointment system and
 demonstrates it. There is no user input and no data is saved: the main
 method plays the part of the users and prints what happens.

 9 health professionals of 5 different types and 4 patients have been created.

========================================================================
 PART 1 & 2 - VALIDATION AND ENCAPSULATION
 Invalid objects must be impossible
========================================================================
  Each constructor checks its arguments and refuses to create a broken
  object. The attempts below are all rejected:

    - identifier with letters  -> A health professional's identifier must contain numbers only, but was "GP-1001".
    - blank name               -> A health professional name must not be blank.
    - unknown shift            -> A shift must be Morning, Evening or Night, but was "Afternoon".
    - impossible time          -> Minute must be between 0 and 59 but was 75.
    - invalid phone number     -> A patient's mobile phone number must be 10 digits, for example 0412345678, but was "0412-ABC".
    - appointment without a patient -> An appointment must have a patient.

  The data itself is private and has no setters, so it cannot be changed
  after creation. getAvailableDays() returns a copy, so this cannot corrupt it:
    - days after clearing the returned copy -> Mon, Wed, Fri (unchanged)
